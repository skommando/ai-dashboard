# 个人项目进度看板：设计草案

日期：2026-09-28。状态：用户已确认用途和下述计量规则；本稿汇总完整方案供审阅，页面布局与技术选型尚待整体对齐。当前交付范围是设计与 HTML demo，不包含后端产品实现或 VPS 部署。

## 1. 使用目标与成功标准

用户在 iPhone 上快速了解 Windows 本机各项目的推进情况：完成了多少、当前在做什么、哪里阻塞、哪些结果等待验收。桌面提供同样的只读信息，并利用较大屏幕并排展示项目和详情。

查看端不连接大模型，不编辑任务，不触发执行或验收。各项目现有的 agent 或脚本调用统一 MCP/HTTP API 更新进度。远程使用本地 Codex 仅做了单独的最小可行性验证，暂不加入看板功能。

用户已确认：

- 项目计划与记录以各项目仓库为准，看板是结构化汇总副本。
- 默认按 Task 数量等权计算，Wave 为分组。
- Task 再拆子项不改变它在项目中的计数；子项用于展示细节。
- Task 实现并通过约定检查即可计为完成，人工验收单独标记。
- 后续 Wave 尚未拆完时，明确展示“已规划范围”的完成情况。
- 本机离线时首版显示离线即可，不建设 VPS 进度副本。
- Task 详情显示简报、阻塞原因和完成依据，不采集完整聊天或执行日志。

## 2. 层级与进度口径

层级采用 `项目 → Wave → Task → 子项（可选）`；项目之下最多三层。没有 Wave 的项目可由接入方放入一个默认阶段，UI 不强制展示冗余层级。

**计量单位固定为 Task。** 设当前纳入计划且未取消的 Task 为 N，其中满足完成标准的 Task 为 D，则已规划范围进度为 `D / N`。各 Wave 使用相同口径计算自己的完成数；项目总进度直接汇总 Task，不平均 Wave 百分比。

例：Wave A 有 2 个 Task，Wave B 有 8 个；A 全部完成、B 未开始时，项目为 `2/10，20%`。A 的一个 Task 拆成三个子项，分母仍为 10；其子项全部完成并不替代该 Task 自身的验证要求。

边界规则：

- N 为 0 时显示“尚未登记任务”，不显示 0% 或 100%。
- 未拆解的未来 Wave 显示“待细化”，不作为一个虚构 Task 计入分母。
- 例如显示“已规划任务 12/20 · 60%，另有 2 个 Wave 待细化”；已规划任务全部完成也不能自动宣称项目交付完成。
- 任务增加、取消或重新打开会影响百分比；记录范围变化与原因，允许真实进度下降。
- 取消任务保留记录并退出分母；删除、归档与取消语义不能混用。这里只定义展示口径，修改仍由项目侧上报。
- 不把代码量、token、运行时长、提交数或主观估计换算为进度。该比例不用于推断剩余工时。

## 3. 状态、验收与新鲜度

Task 的执行状态建议覆盖：未开始、进行中、等待输入、阻塞、已完成、失败、已取消。只有满足约定检查的“已完成”计入 D。验收状态独立表达：无需人工验收、待验收、已验收、需修改。

人工验收只在项目本身规定的 Task、Wave 或项目级门上出现，不默认要求每个 Task 都由用户确认。若验收后需要返工，由项目侧明确重新打开相关 Task，并报告原因。

首页同时保留当前阶段、最新一句进展、待处理事项、最后上报时间。连接状态与任务状态分开：看板连不上后端，不代表 Task 失败；长时间没有新进度也不自动意味着 agent 已停止。首版不承诺监测每个 agent 进程的存活情况。

## 4. 数据来源与更新方式

各项目保留原有计划文档和执行流程，agent 将需要展示的内容结构化上报。首版不依靠大模型阅读日志推测进度，也不建设通用 Markdown 解析器。

建议的数据流：

`项目计划/任务记录 → 项目 agent 或脚本 → 本地上报接口 → SQLite → 只读查询接口 → 浏览器`

首次接入登记项目和计划树，后续在开始任务、关键状态变化、完成验证、范围调整和验收结果变化时更新。上报内容包括稳定的项目/节点 ID、父子关系、执行与验收状态、简报、依据摘要和更新时间。

数据库保存当前展示状态与简短变更记录；根据结构化 Task 状态计算进度，不接收可随意覆盖的项目总百分比。同一项目的更新应原子写入，并具备版本校验和重试去重，防止旧会话覆盖新计划。完整字段和协议在后端实施前制定，本轮 demo 仅使用符合上述语义的静态样例。

MCP 与 HTTP API 共用业务逻辑，MCP 作为项目 agent 的便捷调用入口，HTTP API 用于脚本及其他项目接入，以 OpenAPI 描述。查看端本身不调用模型，也不需要模型密钥。

## 5. 技术与远程访问方案

- 后端：Python，建议采用 FastAPI 提供经过验证的请求结构、只读查询和 OpenAPI 描述。
- 存储：SQLite，保存在 Windows 主机，由本地后端管理。
- 正式前端：建议 Vue 3 + TypeScript + Vite，采用项目自有的 CSS 视觉规则。
- 本轮 demo：原生 HTML/CSS/JavaScript，数据、样式和交互内嵌，避免 CDN、外部字体或后端依赖，便于转发和体验。

访问链路沿用参考项目：

`iPhone / 桌面浏览器 → VPS HTTPS + Nginx Basic Auth → frps/frpc → Windows 只读服务`

参考依据：[部署文档](../../../../cc_remote_workspace/docs/VPS-SETUP.md)、[Nginx 示例](../../../../cc_remote_workspace/tools/nginx-ws.example-user.com.conf)及实际本机 frpc 配置。实际配置使用 frps 控制端口 8070、本地应用端口 8888、VPS 转发端口 8082；部署文档中控制端口示例仍为 7000。新项目后续分配独立端口/入口，不直接覆盖原项目配置。

设计边界：

- 对外只暴露读取服务；上报入口限于本机侧，按项目验证写入身份。建议读取和上报使用独立监听入口，frp 只映射读取入口。
- Basic Auth 位于 HTTPS 入口；VPS 的转发端口应仅供本机 Nginx 使用或经防火墙限制，避免绕过入口鉴权。实施时检查实际配置，而不是复制文档中的全部设置。
- 本地服务不可达时，已打开的页面显示离线且不再将旧数字标成实时；首次打开时可由 VPS 返回一个静态离线说明页。无需同步项目数据到 VPS。
- 只读数据首版采用页面可见时约 15 秒轮询、重新切回页面时立即刷新；不为进度浏览引入完整实时日志流。

技术参考：[FastAPI 特性](https://fastapi.tiangolo.com/features/)、[Vue 渐进式使用方式](https://vuejs.org/guide/introduction.html)。

## 6. 页面与视觉方向

整体采用明亮、安静且有信息密度的工作台：暖灰底色、白色内容面、深灰文字和一处低饱和绿色强调。状态色只服务于含义，配合文字和图形；用细分隔线、统一字阶与留白建立层次。圆角和阴影保持克制，中文正文使用系统字体，进度数字保持对齐。

### 项目总览

顶部简洁标明页面名、连接状态和更新时间，下方为搜索及状态筛选。项目条目展示：项目名、一句当前进展、当前 Wave、已完成 Task/已规划 Task、进度、待处理状态和最近更新时间。

待输入、阻塞、待验收事项有清晰标记；默认优先呈现需要关注的活跃项目，已完成项目收拢到筛选项。已规划范围以文字明确标注，不用装饰性图表代替数字。

### 项目与 Task 详情

项目详情包含简短目标、范围完成情况、Wave 列表和最近进展。展开 Wave 查看 Task；Task 详情展示目标、状态、最新进展、阻塞原因、子项、检查摘要和提交/文件依据。

没有真实远端链接的本地文件路径或提交号只作文本依据，不生成手机上无效的文件跳转。全页面没有编辑、启动、停止、确认验收或聊天输入控件。

### 桌面与手机适配

- 桌面：项目列表与选中详情并排，减少来回跳转；侧栏保持窄，主要空间留给任务信息。
- 手机：单列项目列表，依次进入项目和 Task；保留清楚的返回路径与筛选状态，避免把桌面多栏直接缩小。
- 任务子项逐层展开；不在手机首屏塞入完整任务树。
- 长名称可换行，关键数字和状态不被截断；点击区域与正文为触控阅读留出空间。

信息组织参考：[GOV.UK 任务列表](https://design-system.service.gov.uk/components/task-list/)的任务与状态对应关系、[Linear 项目概览](https://linear.app/docs/project-overview)的信息层次。仅借鉴组织方法，视觉由本项目自行设计。

## 7. HTML demo 的交付与验收

交付一份独立、可转发的响应式 HTML，提供桌面与手机尺寸的预览。两端使用同一组数据与计量规则，不维护两套业务逻辑。手机交互验收建议将该静态 HTML 放到可访问的 HTTP(S) 地址后由 Safari 打开；直接附件预览的能力需要以用户设备上的实际打开方式验证。

demo 展示约 6 个虚构示例项目，清楚标注为演示数据，覆盖：正常推进、阻塞、待验收、已完成、未来 Wave 待细化及尚无 Task。另提供能检查离线、空搜索结果和长名称布局的演示状态。

交互包括项目筛选、搜索、查看详情、Wave 展开、Task/子项下钻和返回。页面里的 Task 状态只读；没有假的执行按钮或聊天功能。

验收以实际浏览器检查为准：

- 1440px 桌面和 390px/430px 手机布局可读；375px 窄屏无非预期横向滚动。
- 完成数与百分比吻合；Task 子项不改变分母；待验收与实施完成同时可见。
- 手机返回后保留合理的筛选和浏览上下文，触控目标容易操作。
- 静态页面无外部资源依赖、无控制台错误；离线和空状态有可理解的文字。
- 浏览器模拟检查与真实 iPhone 体验分开记录；iPhone 实际观感由用户体验后反馈。

如果第一版视觉效果不符合预期，再输出包含本稿规则、页面信息结构、样例数据和视觉约束的 AI Studio 提示词。届时替换视觉实现时仍保留已确认的计量与只读边界。
